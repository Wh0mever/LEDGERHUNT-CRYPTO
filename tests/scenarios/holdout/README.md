# Отложенный набор сценариев — не использовать при разработке

Этот каталог — итоговый (отложенный) набор тестовых сценариев. Он нужен только для итоговой оценки по решению владельцев (раздел 1.5 [stage-2-decisions.md](../../../docs/spec/stage-2-decisions.md)).

## Где лежит содержимое

Сами сценарии (`hold-*/`) и начальное значение генератора (`seed.txt`) хранятся у владельцев и в git не попадают: `.gitignore` исключает всё в этом каталоге, кроме `README.md` и `manifest.json`. В git остаются только этот файл и `manifest.json` — sha256 каждого файла набора (включая `seed.txt`), общий хеш `tree_sha256` и sha256 начального значения (`seed_sha256`). По манифесту владельцы в любой момент докажут, что набор не менялся.

Передача владельцам: архив `handover/holdout-2026-10-14.zip` (папка `handover/` тоже не попадает в git). В архиве весь набор: 27 каталогов `hold-*`, `seed.txt`, `manifest.json` и прежняя версия этого файла, всё под папкой `holdout/`. При создании архив сверен с `manifest.json`: совпали все 1 697 файлов, `seed_sha256` и `tree_sha256`.

Если содержимого нет (обычный клон репозитория), проверки не падают: `python -m ledgerhunt stage2 scenarios` и `python -m ledgerhunt.scenarios verify-holdout` пишут «отложенный набор у владельцев, проверка по манифесту пропущена», а тест целостности в `pytest` пропускается с той же причиной.

## Правила

1. Не открывать, не читать и не анализировать файлы сценариев (`hold-*/`) и `seed.txt` при разработке, настройке или отладке трассировщика, промптов и порогов. Это касается и людей, и AI-агентов.
2. Не запускать на наборе трассировщик до итоговой оценки. Оценщик (`python -m ledgerhunt.scenarios score --split holdout`) отказывается работать без флага `--owner-final-evaluation`.
3. Не изменять файлы. Целостность проверяется по `manifest.json`.
4. Модульные тесты (`pytest`) и прогон `python -m ledgerhunt stage2 scenarios` читают отсюда только хеши и выводят только количества: число сценариев, совпадение хешей, результат повторной генерации, число прошедших структурную проверку.
5. Эталон case-001 в этот набор не входит.

## Что внутри набора

- 27 синтетических сценариев, по 3 в каждой из 9 категорий; варианты и параметры выбраны из отдельного начального значения генератора (seed), не совпадающего с набором для разработки.
- Идентификаторы `hold-NNN` непрозрачны: категория записана только в `expected.json` сценария; в `manifest.json` есть только количества по категориям.

## Как проверить копию по манифесту

1. Распакуйте архив во временный каталог вне репозитория, например `C:\holdout-check`. Появится `C:\holdout-check\holdout\`.
2. Из корня репозитория выполните:
   `python -m ledgerhunt.scenarios verify-holdout --dir C:\holdout-check\holdout`
3. Копия цела, если команда завершилась с кодом 0, а в выводе `"integrity_ok": true`, `"files_matching"` равно `"files_listed"` (1 695: все файлы, кроме `README.md` и `seed.txt`), `"files_unlisted": 0` и `"regeneration": "identical"`. Последнее значит, что `seed.txt` из копии заново порождает тот же набор байт в байт. Команда сверяет копию с `manifest.json` из репозитория, а не с манифестом из архива.

Для итоговой оценки владелец копирует `hold-*/` и `seed.txt` из архива в этот каталог (`README.md` и `manifest.json` не трогать). После этого `python -m ledgerhunt.scenarios verify-holdout` без `--dir` проверяет набор на месте.

## Как владельцам усилить защиту

- Генератор и шаблоны лежат в репозитории, поэтому отложенный набор защищает от подгонки под конкретные сценарии (адреса, суммы, порядок, TXID), но не от подгонки под семейство шаблонов. Для независимой проверки после заморозки кода добавьте сценарии, составленные другим человеком или другой версией генератора, и сценарии на собственных переводах в основной сети.
- Можно создать собственный закрытый набор со своим seed:
  `python -m ledgerhunt.scenarios create-holdout --seed <ваше значение> --out <каталог вне репозитория>`.
