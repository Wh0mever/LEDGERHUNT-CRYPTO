## 5. Языковые модели, наблюдаемость и оценка качества AI-слоя

**Решение.** Primary — Anthropic Claude API: `claude-haiku-5-5` на рутинных шагах, `claude-sonnet-5-5` для планирования и коротких секций отчёта; strong-tier задаётся конфигом. Fallback — OpenAI (`gpt-6-luna`, `gpt-6.1-sol` через Responses API). Доступ — официальные SDK за собственным адаптером LLMClient, без LLM-gateway; источник истины по трассам — своя БД + OpenTelemetry, UI — Arize Phoenix либо Langfuse Cloud EU (по решению владельца о размещении данных); evals — Inspect AI в Linux-контейнере. Статус: условно — до юридического разбора Usage Policy, пилота на 50 сценариях и чтения договора OpenAI.

### Почему выбрано
- Цены и лимиты прочитаны 2026-10-13/14; цены Anthropic совпали в трёх источниках (официальная страница, каталог OpenRouter, cost map LiteLLM). Верификатор перепроверил 26 утверждений аудита: 22 подтверждены, 2 исправлены, 1 опровергнуто, 1 проверить не удалось.
- По расчётной модели бюджет выдерживается: типичное расследование (45 адресов, 106 вызовов) — $0.40, тяжёлое (60 адресов, 158 вызовов, отчёт на русском) — $0.57 при цели <= $1. Проверена только арифметика; объёмы токенов — допущения, не измерено.
- 84% стоимости дают 8 вызовов Sonnet, поэтому strong-tier конфигурируемый, а тело отчёта собирает детерминированный шаблон; LLM пишет только короткие секции (уточнение к G13).
- Structured outputs (`output_config.format`, strict tools) — GA на обеих моделях; ID моделей — pinned snapshots, retirement не ранее 2027-09-28 (Sonnet) и 2027-10-07 (Haiku).
- Gateway при двух провайдерах не оправдан: у LiteLLM за 2026 год 17 advisories (4 critical, 6 high) и компрометация PyPI 2026-03-24; Portkey без коммитов с 2026-05-25, Helicone в maintenance mode.
- Phoenix — одно контейнерное приложение с SQLite или PostgreSQL >= 14; Langfuse self-host — 6 контейнеров и минимум 4 ядра / 16 GiB / 100 GiB, что не помещается на сервер 4 vCPU / 8 GB.
- Inspect AI — MIT, Python-нативный (общий код с платформой), есть batch-режим.

### Лицензия и коммерческое использование
- Anthropic: проприетарный API. Commercial Terms (2025-06-17, раздел A.1) разрешают использование в продуктах для своих клиентов; outputs принадлежат клиенту, обучение на его данных запрещено; нельзя перепродавать доступ и создавать конкурирующие модели.
- Usage Policy Anthropic (редакция, вступающая в силу 2026-11-12) запрещает «identify, unmask, or locate» людей по анонимной или псевдонимной активности с целью слежки или вреда, сбор профилей для раскрытия третьим лицам и подсказку решений в правоохранительной деятельности. Исключения — fraud detection / AML screening по согласию, журналистика, legal research правоохранительных органов; для частных расследователей и потерпевших исключения нет. Прочитаны короткие цитаты; юридический разбор полного текста не проводился.
- OpenAI: Services Agreement получить не удалось (HTTP 403) — коммерческое использование по договору не проверено; политики использования не читались.
- SDK anthropic 1.13.0 — MIT, openai 3.29.0 — Apache-2.0; Inspect AI — MIT. Phoenix — Elastic License 2.0: внутреннее использование в коммерческом SaaS разрешено, предоставлять сам Phoenix клиентам как сервис нельзя. Langfuse Cloud — SaaS-подписка (ядро Langfuse — MIT).

### Состояние проекта и расхождения «заявлено — на деле»
- Haiku 5.5 вышел 2026-10-07, статистики надёжности tool calling нет; реальные вызовы API в аудите не выполнялись.
- Structured outputs заявлены как всегда валидные, но при refusal или max_tokens вывод может не соответствовать схеме; нет рекурсии, minimum/maximum, minLength/maxLength; таймаут компиляции грамматики — 180 с, кеш 24 ч.
- Цена Haiku $0.10 действует до 100K токенов prompt (считая cache read и write), выше — в 5 раз дороже; prompt держим ниже порога.
- Не-default значения temperature и top_p на обеих моделях дают 400; Sonnet 5.5 отвергает forced tool_choice.
- Refusal приходит с HTTP 200 и тарифицируется. У Haiku 5.5 нет server-side fallback; у Sonnet 5.5 он (beta) покрывает только cyber и frontier_llm, а general_harms может срабатывать на добросовестной работе.
- Тезис аудита «Haiku 5.5 и GPT-6 Luna — самые дешёвые модели с vision и structured outputs» опровергнут (gpt-4.1-nano — $0.10 / $0.40 за 1M). На бюджет не влияет: доля Haiku — $0.062 из $0.40.
- OpenAI: заявлен context 1.05M при max input 922K; function calling с reasoning у `gpt-6-luna` — только через Responses API; датированных snapshot ID на странице модели нет.
- Inspect AI 0.3.279 (2026-10-12): релизы дважды в неделю, API может меняться; CI авторов — только ubuntu-latest и Python 3.10/3.11. Phoenix v20.21.2 (2026-10-13): заявлен как open source, фактически ELv2.
- Pydantic AI (G3) в этой области проверен только по метаданным (MIT, v2.55.0; код не читался); коммит от 2026-10-13 показывает, что поддержка native structured outputs Anthropic ещё стабилизируется.

### Инфраструктура и затраты
Цены и лимиты — на 2026-10-13/14.
- Постоянные: ПО — $0 в месяц. Phoenix — один контейнер рядом с PostgreSQL платформы; потребление RAM не измерено. Вариант Langfuse Cloud (с client-side masking): Hobby $0 (50k units в месяц, доступ к данным 30 дней; при допущении 300 units на расследование — около 160 расследований, по нашей оценке это уровень разработки и пилота), Core $29 в месяц (100k units, 90 дней).
- Тарифы за 1M токенов (input / cache write / cache read / output): Haiku 5.5 — $0.10 / $0.125 / $0.01 / $0.50; Sonnet 5.5 — $2 / $2.50 / $0.10 / $10; Batch −50%. У `gpt-6-luna` и `gpt-6.1-sol` базовая сетка та же.
- Переменные на расследование: LLM $0.40-0.57 (оценка); остаток до $1 — $0.43-0.60 на платные data-API и поиск. Из него $0.10-0.25 — резерв на web search: встроенный поиск Anthropic стоит $0.01 за запрос и в модель стоимости не включён; выбор поискового провайдера — открытое решение (G15).
- Anthropic Start tier: 1 000 RPM, 2M ITPM, 400K OTPM на модель; cap $500 в месяц (около 880-1 250 расследований), далее HTTP 429 до 1-го числа. Новая организация может начать в Evaluation tier; его лимиты не опубликованы.
- Eval-прогон 50 сценариев: $20-29 за проход, $60-145 при 3-5 epochs, через Batch вдвое меньше.

### Ограничения и риски
- Usage Policy: OSINT и отчёты для бирж и полиции — серая зона; агент ограничен атрибуцией сервисов и юрлиц, без установления личности физлиц (как в G15), с human review. По документации vision Claude нельзя использовать, чтобы называть людей на изображениях.
- Частота refusal на материалах о кражах, фишинге и отмывании не измерена.
- Латентность не измерена: вызов Sonnet с effort high плюс первая компиляция грамматик может занять больше минуты; нужны параллельные вызовы Haiku, стриминг и прогрев схем при деплое.
- Модель стоимости не учитывает рост input из-за сохраняемых thinking-блоков и повторы при refusal; 16K output на 8 вызовов Sonnet для отчёта на русском выглядит оптимистично. Цены нестабильны: Haiku 5.5 вышел 7 дней назад.
- Данные жертв уходят провайдерам в США: ZDR у Anthropic — только через sales; flagged-контент хранится до 2 лет даже при ZDR, Batch — 29 дней. Маршрут Claude через Vertex AI EU: +10% к цене, обработчик — Google, условия не проверены; на Amazon Bedrock structured outputs для Haiku 5.5 недоступны. Требования GDPR и локализации владельцем не определены.
- В аккаунтах Anthropic, созданных после 2026-08-31, изменение system, tools или истории при возврате thinking-блоков даёт 400: история агентов строго append-only. При fallback thinking-блоки теряются.

### Как проверяем качество
- Eval-набор >= 50 сценариев (JSONL, ground truth, версии в git). Inspect AI вызывает production-пайплайн из собственного solver через тот же LLMClient; 3-5 epochs, парное сравнение с детерминированным baseline.
- Метрики: точность и полнота конечных адресов; точность меток >= 95% на независимом наборе; доля утверждений с TXID — 100%, выдуманных TXID — 0; доля schema-valid ответов; refusal по категориям; латентность; стоимость. Метки и TXID оценивают только детерминированные scorers.
- Пост-валидатор: каждый TXID и адрес из вывода LLM обязан существовать в хранилище фактов, иначе фрагмент отбрасывается; `stop_reason` проверяется до чтения содержимого.
- Адаптер (оценка аудита в 200-400 строк кода занижена): контрактные тесты на mock-ответах обоих провайдеров, расчёт стоимости по трём ценовым режимам, сверка с usage в консолях, тест переключения на fallback.
- Воспроизводимость: журнал хранит model id, SHA-256 prompt и схем, effort, thinking, `anthropic-version`, beta-заголовки, признак fallback, `stop_details.category`, usage и полный ответ. Содержимое отчёта (до подписи и timestamp, раздел G11) пересобирается из журнала без вызовов LLM и совпадает побайтно; дрейф ловит еженедельный canary на 10 сценариях.
- Маскирование: поиск шаблонов API-ключей и seed-фраз по трейсам даёт ноль совпадений.
- Бюджет-трекер: при 70% расхода — только Haiku, при 100% — отчёт без LLM-текста.

### Заменяемость
Высокая. Роли cheap / strong / report задаются конфигом; у пар Anthropic и OpenAI одинаковые базовые цены и context около 1M, привязка — `cache_control`, `output_config` и effort. При переключении на OpenAI меняется API (Responses), теряются thinking-блоки, а пиннинг snapshot не подтверждён. Backend трасс меняется сменой OTLP endpoint; сценарии и scorers — собственные файлы. Любая смена модели, effort или prompt требует перепрогона eval-набора.

### Что проверить до фиксации выбора (Этап 2)
1. Юридический разбор Usage Policy Anthropic и политик OpenAI; критерий — письменное заключение о допустимости атрибуции сервисов и юрлиц с human review.
2. Пилот на 50 сценариях: доля refusal по категориям, латентность (<= 30 с и <= 2 мин), фактический usage (<= $1 вместе с data-API и поиском); заявка в Cyber Verification Program.
3. Eval трёх strong-tier: Sonnet 5.5, Haiku 5.5 с effort high, Mistral Large 4 или Grok 4.3; критерий — самый дешёвый вариант, который статистически превосходит baseline при точности меток >= 95%.
4. Ручное чтение OpenAI Services Agreement и проверка пиннинга snapshot GPT-6 до включения fallback.
5. Сравнение Phoenix и MLflow tracing на реальном трейсе (1-2 дня) и замер RAM на сервере 4 vCPU / 8 GB.
6. Inspect AI в Linux-контейнере с точной версией; проверка на Python 3.13.
7. Лимиты Evaluation tier и срок хранения данных Anthropic без ZDR.
8. В спайке G3: вызовы Pydantic AI проходят через LLMClient (журнал, стоимость, fallback) и дают schema-valid ответы на схемах проекта.
9. Решения владельца: размещение трасс (Phoenix на своём сервере или Langfuse Cloud EU), нужен ли ZDR, язык отчётов.
