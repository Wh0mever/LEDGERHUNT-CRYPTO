## 12. Генерация отчётов в JSON и PDF, целостность доказательств

**Решение.** JSON-отчёт строится из моделей Pydantic 2.14 с публикуемой JSON Schema 2020-12 и полем `schema_version` (SemVer). PDF рендерит WeasyPrint ≥ 70.0 с шаблонами Jinja2 в изолированном Linux-контейнере: архивный формат PDF/A-3 с вложениями, отдельная асинхронная задача вне сроков 30 с / 2 мин / 5 мин. Целостность обеспечивают двухуровневый манифест, каноническая запись JSON по RFC 8785, подпись Ed25519 и метка времени RFC 3161 от службы меток времени (TSA); OpenTimestamps — дополнительный слой. Статус: условно, до замера скорости рендера и проверочной реализации (spike) схемы печати на Этапе 2. Одноуровневая схема из первичного исследования перепроверку не прошла: в ней цикл хешей.

### Почему выбрано
- Один HTML/CSS-шаблон даёт веб-версию и PDF; WeasyPrint работает без браузера (G10). По исходному коду подтверждены опции `--attachment`, `--pdf-variant`, `--pdf-identifier`; по changelog вложения для PDF/A есть с 61.0, воспроизводимый PDF — с 55.0.
- Pydantic 2.14.1 (2026-10-11) и python-jsonschema 4.26.0 поддерживают Python 3.13. TXID у факта и поля source, checked_at, confidence у метки обязательны в модели: отчёт без них не сериализуется.
- Готового стандарта не найдено: в STIX 2.1 (стандарт OASIS) нет штатных объектов для адресов и транзакций; в UCO 1.5.0 (онтология цифровых расследований) поиск по слову cryptocurrency даёт 0 совпадений, issue #675 открыт с 2026-03-26; IVMS101 описывает данные отправителя и получателя перевода, а не доказательства.
- Слои печати отвечают на разные вопросы: хеши — неизменность, Ed25519 — выпуск платформой, RFC 3161 — существование не позже момента T, OpenTimestamps — привязка к блокчейну Bitcoin без доверенной стороны. В службу меток времени уходит только хеш.
- rfc3161-client 1.0.9 (Trail of Bits, 2026-09-14) сетевых вызовов не делает: запрос к TSA идёт через общий HTTP-шлюз (G4); есть готовые сборки (wheels) для Windows.
- Письма биржам, Tether и правоохранительным органам — собственные шаблоны Jinja2 (RU/EN) на том же движке: три поисковых запроса по GitHub дали 0 готовых шаблонов, машинного стандарта запроса не найдено.

### Лицензия и коммерческое использование
WeasyPrint — BSD-3-Clause (текст LICENSE прочитан); Pydantic и jsonschema — MIT; rfc8785 и rfc3161-client — Apache-2.0. По нашему прочтению, коммерческое использование разрешено; условие MIT — сохранять уведомление об авторских правах и текст лицензии, у BSD и Apache-2.0 требования сходные. opentimestamps-client (LGPL-3.0-or-later) и docxtpl для писем в DOCX (LGPL-2.1-only) используются как библиотеки в SaaS без распространения; veraPDF (валидатор PDF/A, GPL-3.0) запускается отдельным CLI в CI. По нашему прочтению, обязательств на код платформы это не создаёт. Не проверены условия: FreeTSA для компаний, публичной службы Sigstore (политика и лимиты), публичных календарей OpenTimestamps, двойного лицензирования veraPDF.

Первичное исследование ссылалось на PR #2808 (0.94 с на 1 200 строк): PR закрыт без слияния, цифра снята на форке автора, оптимизация вошла через PR #2813, замеров на 70.0 нет. В обсуждении PR мейнтейнер пишет, что скорость не приоритет.

- rfc8785 0.1.4 (2024-09-27, 13 stars) отказывает на целых вне ±(2^53 − 1); сырое значение USDT с 6 знаками выходит за предел примерно на 9.007 млрд USDT. У rfc3161-client 7 stars.
- opentimestamps-client: последний релиз 0.7.2 — 2024-12-31; календари отвечали на запросы 2026-10-14.

Для жертвы возврат идёт через правоохранительные органы; TRM Beacon Network, сеть обмена сигналами о похищенных средствах, заявляет доступ для проверенных компаний по безопасности (только по странице TRM, условия не проверены).

### Инфраструктура и затраты
- Контейнер-воркер report-renderer: python:3.13-slim, Pango ≥ 1.44, шрифты с кириллицей (Noto, DejaVu, PT); без исходящей сети и без Ghostscript. Память 200–500 МБ на большой документ — оценка, не измерена. На Windows рендер идёт только в Docker.
- Постоянные затраты: $0 в месяц за лицензии; используется CPU общего сервера (раздел 13). veraPDF требует JVM и работает только в CI.
- Переменные затраты на расследование: секунды CPU (не измерены) и одна метка времени — $0 у бесплатных служб, ориентир €0.03–0.04 у коммерческой или квалифицированной (по поисковым сниппетам от 2026-10-13/14, цены не подтверждены). Метка — отдельная статья бюджета расследования и входит в общий лимит $1.00 (G17).
- Бесплатно только для разработки: FreeTSA, публичная служба Sigstore, календари OpenTimestamps; для платного продукта закладывается коммерческая служба меток времени. Юридическая вычитка писем — разовая, вне оценки.

### Ограничения и риски
- Схема печати. Манифест содержимого (content-manifest: хеши `report.json`, изображения графа и сырых ответов API, без PDF) вкладывается в PDF/A-3, его хеш печатается в колонтитуле. Манифест пакета (package-manifest: хеши `report.pdf` и content-manifest, версии моделей) проходит RFC 8785 → Ed25519 → RFC 3161 → OpenTimestamps и лежит в архиве доказательств рядом с цепочкой сертификатов TSA.
- Сроки. 30 с / 2 мин / 5 мин считаются от постановки задачи до проверенного JSON-отчёта, показанного в интерфейсе. PDF, подпись и метка времени — отдельная асинхронная задача (G11): манифест пакета содержит хеш PDF, поэтому подписанный пакет готов только после рендера. Его целевой срок утверждают владельцы.
- Состав. В отчёт входят только данные из блоков, подтверждённых сетью (solidified; отставание 18–19 блоков, 54–57 с). Пакет для клиента содержит TXID, хеши сырых ответов и манифест; сами ответы остаются на платформе, пока провайдеры письменно не разрешили их передачу (G11).
- Пакет для потенциальной биржи. Для каждого адреса, который отчёт относит к бирже или к кандидатам в биржу, формируется отдельный пакет: переводы на адрес с TXID, хеши квитанций и ответов провайдеров, источник, дата проверки и достоверность метки, свой манифест.
- Все суммы и сырые значения — десятичные строки плюс поле `decimals`; float в модели запрещён.
- Время и память рендера для графа на 1 000 адресов не измерены, как и число строк TXID: расчёт запросов (раздел 1) исходит из тысяч рёбер, замер берёт запас до 50 000 строк. Длинные таблицы верстаются с `table-layout: fixed` или блоками; выше порога полный список TXID уходит во вложение CSV/JSON, в теле остаются агрегаты.
- В HTML попадают строки под контролем злоумышленника (имена токенов, memo, внешние метки). Меры: autoescape, собственный URLFetcher с запретом загрузок, закреплённая версия. Gotenberg, если владельцы его разрешат, — только во внутренней сети, без webhook и downloadFrom.
- Ключ Ed25519 на сервере приложения снижает доказательную ценность подписи (хранение — раздел 13). При недоступности службы меток времени отчёт помечается `timestamp pending`; юридическая сила метки зависит от юрисдикции.
- WeasyPrint не исполняет JavaScript, его SVG-рендерер ограничен: граф вставляется готовым изображением, которое сервер рисует из снимка расследования (G10). SVG из Graphviz (кандидат раздела 9) требует проверки, запасной вариант — PNG 2x.
- Письма не обещают заморозку и возврат средств (G15) и не выдаются за требования получателя.

### Как проверяем качество
- Схема: все сценарии тестового набора (не менее 50 с точно известным ответом) проходят валидацию по опубликованной схеме; автотест: нет факта без TXID и метки без источника, даты проверки и достоверности; отчёты прошлых minor-версий читаются; `report.json` каноникализуется rfc8785 без исключений, хеш стабилен между запусками.
- PDF: эталонные тесты — библиотека pypdf 6.20.1 находит каждый TXID из `report.json`, число ссылок-аннотаций равно числу TXID; нет глифов .notdef на тексте с кириллицей и латиницей; veraPDF v1.30.3 подтверждает PDF/A-3; sha256 вложенного JSON совпадает с манифестом содержимого.
- Печать: пересчёт sha256 артефактов, проверка Ed25519, проверка токена TSA через VerifierBuilder с закреплённым корневым сертификатом, `ots upgrade/verify` через 24 ч, негативный тест с изменением одного байта, публичный CLI verify для получателя.
- Пакеты для бирж: число пакетов равно числу таких адресов в отчёте; сырых ответов провайдеров в клиентском пакете нет.
- Письма: тест на незаполненные плейсхолдеры; поля только из фактов отчёта; у каждого поля в реестре получателей — источник и дата ручной проверки, иначе пометка `unverified`.

### Заменяемость
Высокая. Движок PDF скрыт за интерфейсом `render(html, assets) -> pdf`: Gotenberg и PlutoPrint принимают тот же HTML (ограничения по PDF/A — в таблице выше); для Typst — средняя, шаблоны не переносятся. Наружу отдаётся стандартная JSON Schema. Служба меток времени и слой OpenTimestamps меняются конфигурацией. Шаблоны писем — текстовые файлы.

### Что проверить до фиксации выбора (Этап 2)
1. Замер WeasyPrint 70.0 и PlutoPrint 0.22.0 на 1 000, 5 000, 10 000 и 50 000 строк на стенде замеров (раздел 13); пороги времени и памяти задаются до замера (ориентир первичного исследования — не более 20 с на 5 000 строк). При провале — вынос списка во вложение либо Gotenberg по решению владельцев (G10) с пересмотром объёма памяти.
2. Проверочная реализация (spike) двухуровневого манифеста: veraPDF и verify проходят, изменение одного байта обнаруживается, повторный рендер даёт идентичный PDF.
3. Рендер кириллицы и встраивание шрифтов: до сих пор не проверены.
4. Не менее двух независимых служб меток времени: условия публичной службы Sigstore, подтверждённые цены коммерческой службы, тестовые запросы (до сих пор не отправлялись).
5. Ручная сверка требований Binance, OKX и Tether; условия вступления в TRM Beacon Network; юридическая вычитка писем.
6. Формат изображения графа в PDF: SVG или PNG 2x (G10).
7. Состав отдельного пакета доказательств для потенциальной биржи.
8. Решения владельцев: целевой срок готовности PDF и подписанного пакета; нужна ли квалифицированная метка времени (по регламенту ЕС eIDAS) или подпись PAdES — по умолчанию в MVP нет; допустим ли Gotenberg с Chromium как запасной движок (G10).
