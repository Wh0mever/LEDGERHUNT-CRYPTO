## 12. Генерация отчётов в JSON и PDF, целостность доказательств

**Решение.** JSON-отчёт строится из моделей Pydantic 2.14 с публикуемым JSON Schema 2020-12 и полем `schema_version` (SemVer); PDF рендерит WeasyPrint ≥ 70.0 + Jinja2 в изолированном Linux-контейнере (PDF/A-3 с вложениями, асинхронная задача). Целостность обеспечивают двухуровневый manifest, каноникализация RFC 8785, подпись Ed25519 и метка времени RFC 3161; OpenTimestamps — дополнительный слой. Статус: условно, до бенчмарка рендера и spike схемы печати на Этапе 2; одноуровневая схема из аудита проверку не прошла из-за цикла хешей.

### Почему выбрано
- Один HTML/CSS-шаблон даёт web-версию и PDF; WeasyPrint работает без браузера (G10). По исходникам подтверждены опции `--attachment`, `--pdf-variant`, `--pdf-identifier`; по changelog PDF/A есть с 56.0, вложения для PDF/A — с 61.0, воспроизводимый PDF — с 55.0.
- Pydantic 2.14.1 (2026-10-11) и python-jsonschema 4.26.0 поддерживают Python 3.13. TXID у факта и поля source, checked_at, confidence у метки обязательны в модели: отчёт без TXID не сериализуется.
- Готового стандарта нет: в STIX 2.1 нет штатных объектов для адресов и транзакций, в UCO 1.5.0 поиск по слову cryptocurrency даёт 0 совпадений (issue #675 открыт с 2026-03-26), IVMS101 описывает Travel Rule.
- Слои печати отвечают на разные вопросы: хеши — неизменность, Ed25519 — выпуск платформой, RFC 3161 — существование не позже момента T, OpenTimestamps — привязка к Bitcoin без доверенной стороны. К TSA уходит только хеш.
- rfc3161-client 1.0.9 (Trail of Bits, 2026-09-14) сетевых вызовов не делает: запрос к TSA идёт через общий HTTP-шлюз (G4); есть wheels для Windows.
- Письма биржам, Tether и правоохранительным органам — собственные Jinja2-шаблоны (RU/EN) на том же движке: три запроса по GitHub дали 0 готовых шаблонов, машинного стандарта запроса нет.

### Лицензия и коммерческое использование
WeasyPrint — BSD-3-Clause (текст LICENSE прочитан); Pydantic и jsonschema — MIT; rfc8785 и rfc3161-client — Apache-2.0. opentimestamps-client (LGPL-3.0-or-later) и docxtpl для писем в DOCX (LGPL-2.1-only) используются как библиотеки в SaaS без распространения и обязательств на код платформы не создают. veraPDF (GPL-3.0) запускается отдельным CLI в CI. Коммерческое использование этих библиотек разрешено. Не проверено: условия FreeTSA для компаний (ToS нет), политика и лимиты публичного Sigstore TSA, условия публичных календарей OpenTimestamps, условия двойного лицензирования veraPDF.

### Состояние проекта и расхождения «заявлено — на деле»

Аудит ссылался на PR #2808 (0.94 с на 1 200 строк): PR закрыт без слияния, цифра снята на форке автора, оптимизация вошла через PR #2813, замеров на 70.0 нет. Мейнтейнер заявляет, что скорость не приоритет; issue #578 о длинных документах открыт с 2018-02-22.
- PDF/A: аудит называл версию 67.0, фактически поддержка есть с 56.0; документация валидность результата не гарантирует.
- У WeasyPrint 5 advisories, из них 4 опубликованы в 2026 году, включая RCE через EPS и Ghostscript (исправлено в 70.0) и SSRF.
- rfc8785 0.1.4 (2024-09-27, 13 stars) отказывает на целых вне ±(2^53 − 1); сырое значение USDT с 6 знаками выходит за предел примерно на 9.007 млрд USDT. У rfc3161-client 7 stars: обе библиотеки малые.
- opentimestamps-client 0.7.2 от 2024-12-31, развитие медленное; календари отвечали на запросы 2026-10-14.
- Тезис аудита об отсутствии опубликованных крипто-расширений STIX опровергнут: есть muchdogesec/stix2extensions (Apache-2.0, 5 stars, не стандарт OASIS).
- Требования Binance, OKX и Tether к запросам — не проверено (страницы вернули ECONNRESET и 404). Тезис о закрытости всех каналов для негосударственных участников слишком широк: TRM Beacon Network заявляет доступ для проверенных security-компаний (источник — только страница TRM).

### Инфраструктура и затраты
- Worker-контейнер report-renderer: python:3.13-slim, Pango ≥ 1.44, шрифты с кириллицей (Noto, DejaVu, PT); без исходящей сети и без Ghostscript. Память 200–500 МБ на большой документ — оценка, не измерено. На Windows рендер идёт только в Docker.
- Фиксированные затраты: $0 в месяц за лицензии; используется CPU общего сервера (раздел 13). veraPDF требует JVM и работает только в CI.
- Переменные затраты на расследование: секунды CPU (не измерено) и одна метка времени — $0 у бесплатных TSA, ориентир €0.03–0.04 у коммерческого или квалифицированного TSA (поисковые сниппеты, прочитаны 2026-10-13/14, не проверено). При таких ценах лимит $1 соблюдается.
- Бесплатно только для разработки: FreeTSA, публичный Sigstore TSA, календари OpenTimestamps; для платного продукта закладывается коммерческий TSA. Юридическая вычитка писем — разовая, вне оценки.

### Ограничения и риски
- Схема печати. Content-manifest (хеши `report.json`, изображения графа и сырых ответов API, без PDF) вкладывается в PDF/A-3, его хеш печатается в колонтитуле. Package-manifest (хеши `report.pdf` и content-manifest, версии моделей) проходит JCS → Ed25519 → RFC 3161 → OpenTimestamps и лежит в evidence-zip рядом с цепочкой сертификатов TSA.
- Все суммы и raw value — decimal string плюс поле `decimals`; float в модели запрещён.
- Время и память рендера для графа на 1 000 адресов (тысячи и десятки тысяч строк TXID) не измерены. PDF вынесен из целей 30 с и 2 мин (G11); длинные таблицы верстаются с `table-layout: fixed` или блоками, выше порога полный список TXID уходит во вложение CSV/JSON, в теле остаются агрегаты.
- В HTML попадают строки под контролем злоумышленника (имена токенов, memo, внешние метки). Меры: autoescape, собственный URLFetcher с запретом загрузок, закреплённая версия. Gotenberg, если понадобится, — только во внутренней сети, без webhook и downloadFrom.
- Ключ Ed25519 на сервере приложения снижает доказательную ценность подписи (хранение — раздел 13). При недоступности TSA отчёт помечается `timestamp pending`; юридическая сила метки зависит от юрисдикции.
- WeasyPrint не исполняет JavaScript, его SVG-рендерер ограничен: граф вставляется готовым изображением. Кандидат G10 (SVG из Graphviz) поэтому требует проверки, запасной вариант — PNG 2x.
- Письма не обещают заморозку и возврат средств (G15) и не выдаются за требования получателя.

### Как проверяем качество
- Схема: 50+ сценариев проходят валидацию по опубликованной схеме; property-тест на отсутствие Fact без txid; чтение отчётов прошлых minor-версий; `report.json` каноникализуется rfc8785 без исключений, хеш стабилен между запусками.
- PDF: golden-тесты — pypdf 6.20.1 находит каждый TXID из `report.json`, число link-аннотаций равно числу TXID; нет .notdef на тексте кириллица + латиница; veraPDF v1.30.3 подтверждает PDF/A-3; sha256 вложенного JSON совпадает с content-manifest.
- Печать: пересчёт sha256 артефактов, проверка Ed25519, проверка токена TSA через VerifierBuilder с закреплённым корневым сертификатом, `ots upgrade/verify` через 24 ч, негативный тест с изменением одного байта, публичный CLI verify для получателя.
- Письма: тест на незаполненные плейсхолдеры; поля только из фактов отчёта; у каждого поля в реестре получателей — источник и дата ручной проверки, иначе пометка `unverified`.

### Заменяемость
Высокая. Движок PDF скрыт за интерфейсом `render(html, assets) -> pdf`: Gotenberg и PlutoPrint принимают тот же HTML, но у Gotenberg PDF/A делается пост-обработкой, а у PlutoPrint PDF/A и вложения не заявлены; для Typst — средняя, шаблоны не переносятся. Наружу отдаётся стандартный JSON Schema. TSA и слой OpenTimestamps меняются конфигурацией. Шаблоны писем — текстовые файлы.

### Что проверить до фиксации выбора (Этап 2)
1. Бенчмарк WeasyPrint 70.0 и PlutoPrint 0.22.0 на 1 000, 5 000, 10 000 и 50 000 строк на эталонном сервере; пороги времени и RSS задаются до замера (ориентир аудита — не более 20 с на 5 000 строк). При провале — вынос списка во вложение либо Gotenberg с пересмотром G10 и объёма RAM.
2. Spike двухуровневого manifest: veraPDF и verify проходят, изменение одного байта обнаруживается, повторный рендер даёт идентичный PDF.
3. Рендер кириллицы и встраивание шрифтов — в аудите не проверено.
4. Не менее двух независимых TSA: условия публичного Sigstore TSA, подтверждённые цены коммерческого TSA, тестовые запросы (в аудите не отправлялись). Решение владельцев, нужна ли квалифицированная метка (eIDAS) или подпись PAdES.
5. Ручная сверка требований Binance, OKX и Tether; условия вступления в TRM Beacon Network; юридическая вычитка писем.
6. Формат графа в PDF (G10): SVG из Graphviz или PNG 2x.
