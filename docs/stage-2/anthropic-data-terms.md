# Условия Anthropic: хранение и использование данных API

Сводка к решению 1.4 в [stage-2-decisions.md](../spec/stage-2-decisions.md): что Anthropic делает с данными, которые мы отправляем в Claude API как коммерческий клиент, и что из этого следует для отправки материалов пострадавших после их согласия. Все документы прочитаны 2026-10-14; ссылки — в конце, в тексте обозначены [A1], [A2] и т. д. Цитаты минимальные, остальное — пересказ. Это не юридическое заключение; вопросы юристу — в [lawyer-questions-uz.md](lawyer-questions-uz.md).

## 2. Сроки хранения

- **Стандарт для коммерческих клиентов** [A4]: входные и выходные данные API автоматически удаляются на стороне Anthropic в течение 30 дней с момента получения или создания.
- **Помеченное системами безопасности** [A3][A4]: если запрос помечен автоматическими системами trust and safety, входы и выходы хранятся до 2 лет, оценки классификаторов — до 7 лет. Это действует и при zero data retention.
- **Обратная связь** [A4]: если мы сами отправим отзыв (оценку ответа, сообщение об ошибке), связанные данные хранятся 5 лет. Отзывы с материалами клиентов не отправлять.
- **По закону** [A3][A4]: данные могут храниться, если этого требует закон (legal hold).
- **Расхождение в документации.** Страница [A3] в разделе о принципах хранения говорит, что содержимое переписки (промпты и ответы) по умолчанию не хранится, за исключением моделей Fable и Mythos с обязательным хранением 30 дней. Центр конфиденциальности [A4] говорит об удалении в течение 30 дней. В расчётах исходим из более консервативного: до 30 дней.
- **Отдельные функции** [A3]:
  - Batch API — хранение 29 дней;
  - Files API — файлы хранятся до явного удаления или истечения заданного срока;
  - структурированный вывод и инструменты со `strict: true` — промпты и ответы не хранятся, но JSON-схема кешируется до 24 часов после последнего использования;
  - кеш промптов — представления кеша держатся в памяти на время жизни кеша;
  - Console и Workbench — под zero data retention не подпадают.

## 3. Обучение моделей

- Commercial Terms, раздел B: Anthropic не может обучать модели на Customer Content из Services [A1].
- Документация: сохранённые данные не используются для обучения без явного разрешения клиента [A3].
- Обратная связь (п. 2) хранится отдельно; передавать её с материалами клиентов не нужно.

## 4. Zero data retention (ZDR)

- Оформляется только через отдел продаж, отдельно для каждой организации [A3].
- Покрывает Messages API и подсчёт токенов для допустимых функций; не покрывает Batch API, Files API, Console, Managed Agents, выполнение кода [A3].
- Помеченный системами безопасности контент и данные по требованию закона хранятся и при ZDR (до 2 лет) [A3].
- При ZDR не поддерживаются запросы из браузера (CORS) — для нас неважно, вызовы идут с сервера [A3].
- Для нашего объёма ZDR не обязателен: при стандартных условиях данные удаляются в течение 30 дней. Нужен ли он — решение владельца после ответа юриста.

## 5. Где обрабатываются и хранятся данные

- **Место обработки запроса** [A5]: параметр `inference_geo`. По умолчанию `global` — обработка может идти в любой доступной географии. Значение `us` — только в инфраструктуре США; для моделей Claude 4.6 и новее цена ×1.1 [A5][A10].
- **Место хранения** [A5]: workspace geo определяет, где данные хранятся и где выполняется обработка на стороне эндпоинта (например, перекодирование изображений). Сейчас доступно только значение `us`.
- **Субпроцессоры** [A6] (20 записей, без даты): облачная инфраструктура Google Cloud Platform, Amazon Web Services, Microsoft Azure — «Worldwide»; Cloudflare (маршрутизация трафика) — «Worldwide (Local to Customer)»; остальные — оплата, поддержка, рассылки, защита от мошенничества, веб-поиск (Stripe, WorkOS, Intercom, Nutun в ЮАР, Boldr в Канаде, Twilio, Iterable, Sentry, Sift, Arkose Labs, Brave Search, TurboPuffer и другие), часть из них — только для потребительских продуктов.
- **DPA** [A2]:
  - для персональных данных клиента мы — контролёр, Anthropic — наш обработчик (B.1);
  - о новом субпроцессоре Anthropic уведомляет заранее, возразить можно в течение 15 дней, иначе согласие считается данным (C.3);
  - об инциденте безопасности Anthropic уведомляет без неоправданной задержки и не позже 48 часов (G.1);
  - после прекращения договора — возврат или выгрузка данных и удаление в течение 30 дней, с исключениями (H.1);
  - механизмы трансграничной передачи прописаны для ЕС, Великобритании и Швейцарии (стандартные договорные условия); для других стран, включая Узбекистан, отдельного механизма нет.
- **EU-U.S. Data Privacy Framework.** В Privacy Policy Anthropic (действует с 2026-09-10) DPF не упоминается, механизм передачи — стандартные договорные условия [A11]. Реестр участников DPF проверить не удалось. Это важно: постановление Кабинета Министров Узбекистана № 415 включает США в перечень государств с адекватной защитой только для компаний — участников DPF.

## 6. Commercial Terms: что важно нам

- **L.1:** клиент заверяет, что у него есть все права и разрешения на передачу входных данных (Inputs). Значит, согласие клиента на передачу его материалов — наша обязанность [A1].
- **D.2:** действует Supported Regions Policy; Узбекистан в списке [A9]. Россия и Китай в списке отсутствуют.
- **D.4:** нельзя использовать сервис для создания конкурирующих продуктов и перепродавать его без согласия Anthropic [A1].
- **M.8:** экспортные и санкционные ограничения [A1].

## 7. Usage Policy: что относится к расследованию краж

Опубликован текст, действующий с 2026-11-12 [A7]; до этой даты действует версия от 2025-09-15 [A8] (её мы видели только в пересказе инструментом чтения страниц). Ниже — по версии с 2026-11-12.

- **Отслеживание людей и их имущества.** Запрещено отслеживать человека или его имущество без его согласия, наблюдая за местоположением, перемещениями, онлайн-активностью, коммуникациями или связями, в том числе по ранее собранным данным. Исключение: анализ, на который человек согласился, например для выявления мошенничества или проверки по AML на финансовом счёте. **Это главный риск для сервиса:** трассировка средств идёт по адресам, которые контролирует не клиент, а предполагаемый вор, и его согласия нет. Наше прочтение: мы анализируем движение похищенного у клиента имущества по псевдонимным адресам и атрибутируем только сервисы и организации (G15), а не людей. Но допустимость этого нужно подтвердить письменно у Anthropic и у юриста до production.
- **Деанонимизация.** Запрещено устанавливать личность или местонахождение людей по анонимной или псевдонимной активности и собирать досье с целью преследования, запугивания, слежки или вреда. Атрибуция адресов к людям — вне сервиса.
- **Распознавание лиц, биометрия.** Распознавание лиц указано среди запрещённых способов наблюдения; запрещены доступ без разрешения и злоупотребление биометрическими данными. На скриншотах мы закрашиваем лица и не просим модель определять, кто изображён.
- **Правоохранительная деятельность.** Запрещено принимать или предлагать решения в процессах правоохранительных органов и уголовного правосудия (возбуждение расследования, обвинение, арест и т. д.). Отчёт — это изложение фактов для пострадавшего, а не рекомендация органам, кого преследовать.
- **Высокорисковые области: юридическая.** К ней отнесена подготовка юридических документов, которые человек подпишет или подаст, и советы о его правах и обязанностях в конкретном деле. Для таких рекомендаций обязательны проверка квалифицированным человеком до передачи и сообщение человеку, что использовался AI. Заявление в полицию и письма, которые подаёт пострадавший, сюда относятся: шаблоны проверяет человек (сейчас — владелец), в документе указывается участие AI.
- **Высокорисковые области: финансы.** Персональные рекомендации купить, продать, держать или распределить конкретные инвестиционные продукты, включая цифровые активы. Сервис таких рекомендаций не даёт.
- **Чат-боты для потребителей.** Нужно сообщать пользователю, что он общается с AI, а не с человеком, как минимум в начале каждой сессии или в интерфейсе.
- **Мошенничество.** Запрещено содействовать мошенничеству, фишингу и т. п.; наш сценарий обратный, но тексты мошенников на скриншотах — это данные, а не инструкции (решение 1.4).

## 8. Что это значит для отправки скриншотов пострадавших

1. **Согласие до первой отправки.** Отдельное явное согласие на передачу за границу: провайдер — Anthropic PBC, США; обработка может идти и в других странах, где работают его облачные субпроцессоры, если не включить `inference_geo: "us"`. Черновик — [client-consent-draft.md](client-consent-draft.md).
2. **Только Messages API, изображения прямо в запросе.** Не использовать Batch API (29 дней хранения) и Files API (хранение до удаления) для материалов клиентов. Пакетный режим — только для синтетических сценариев и публичных данных блокчейна.
3. **Минимизация до отправки.** Закрашивать лица, документы, телефоны, посторонние переписки; удалять метаданные изображений; отправлять только нужные фрагменты (см. черновик согласия).
4. **Seed-фразы и приватные ключи в модель не уходят.** Входной фильтр срабатывает до сохранения и до вызова модели (G16, решение 1.4).
5. **Никаких персональных данных в JSON-схемах** структурированного вывода: схемы кешируются до 24 часов отдельно от сообщений.
6. **Не вставлять материалы клиентов в Console и Workbench** при отладке: на них ZDR не распространяется, и это лишняя передача.
7. **Выбор `inference_geo`.** `us` даёт одну страну обработки (проще согласие и, возможно, вопросы юриста), но дороже на 10%. Решение — после ответа юриста; до него в замерах используются только синтетические скриншоты.
8. **Срок у Anthropic — до 30 дней, помеченное — до 2 лет.** Это нужно честно указать в согласии; удалить данные у Anthropic по запросу клиента в стандартном режиме мы не можем.
9. **Проверка человеком и пометка об AI** для заявлений и писем, которые подаёт клиент (Usage Policy, юридическая область).
10. **Сообщение «вы общаетесь с AI»** в начале каждой сессии чата.
11. **Журнал без содержимого.** В наших журналах вызовов модели хранятся хеши и метаданные; сами материалы — только в хранилище персональных данных по юрисдикции клиента (решение 1.3).

- Участвует ли Anthropic в EU-U.S. Data Privacy Framework (реестр dataprivacyframework.gov не проверен).
- Текст Usage Policy от 2025-09-15, действующей до 2026-11-12, прочитан только в пересказе.
- Допустимость трассировки средств по адресам третьих лиц с точки зрения пункта Usage Policy об отслеживании имущества без согласия — нужен письменный ответ Anthropic (через отдел продаж или поддержку) и мнение юриста.
- Уровень организации (Start или Evaluation) и его фактические лимиты — видны только в Console владельца.
- Нужен ли ZDR — решение владельца.
