## Одна команда

Нужен Python 3.12 или новее. Из корня репозитория, в PowerShell или Git Bash:

```
python run_stage2.py
```

Скрипт:
1. создаёт виртуальное окружение `.venv`, если его нет;
2. ставит пакет `ledgerhunt` в режиме разработки с зависимостями для тестов, версии берутся из `requirements.lock` (повторная установка пропускается, если `pyproject.toml` и `requirements.lock` не менялись);
3. запускает `python -m ledgerhunt stage2 all` внутри `.venv`.

Флаги:

| Флаг | Что делает |
|---|---|
| `--only tron_sources,case001` | запустить только перечисленные разделы; `--only none` — ничего не запускать, только проверить установку (smoke check) |
| `--llm` | разрешить платные вызовы Claude (раздел `llm_models`); без флага раздел пропускается |
| `--replay` | офлайн: все HTTP-запросы обслуживаются из сохранённых сырых ответов; если ответа нет — понятная ошибка, код выхода 3 |
| `--reinstall` | принудительно переустановить пакет |

Разделы (порядок запуска `all`):

| Имя | Пункт задания |
|---|---|
| `tron_sources` | 4.1 Источники данных TRON |
| `bridges` | 4.2 Мосты и Ethereum |
| `case001` | 4.5 Эталонный прогон case-001 |
| `scenarios` | 4.6 Тестовые сценарии |
| `llm_models` | 4.4 Модели Claude (только с `--llm`) |
| `projection` | 4.3 Расчёт по замерам |

Другие команды (внутри `.venv`: `.venv\Scripts\python` в PowerShell, `.venv/Scripts/python` в Git Bash):

- `python -m ledgerhunt env` — версии, профиль машины и какие ключи заданы (только да/нет);
- `python -m ledgerhunt probe-sources [--replay]` — проверка всех эндпоинтов источников несколькими запросами без ключей по идентификаторам case-001;
- `python -m pytest` — модульные тесты (без сети и ключей).

## Ключи

- Ключи хранятся только в файле `.env` в корне репозитория (он в `.gitignore`) или в переменных окружения. Список переменных с пояснениями — в [.env.example](../../.env.example).
- Переменные окружения имеют приоритет над `.env`. Значения из `.env` не экспортируются в окружение процесса: их читает только `ledgerhunt.core.config`.
- Каждое загруженное значение ключа регистрируется в модуле маскировки. В журналы, индекс сырых ответов, метрики и результаты ключи не попадают: вместо них `***`. В `config.json` каждого замера записывается только факт наличия ключа (true/false).
- Ключ TronGrid передаётся только заголовком `TRON-PRO-API-KEY`. URL платных провайдеров (`TRON_RPC_URL`, `ETH_RPC_URL`) целиком считаются секретом, так как провайдеры встраивают ключ в URL.
- Клиент Anthropic создаётся только через `make_anthropic_client()` и всегда обращается к `https://api.anthropic.com`; переменная `ANTHROPIC_BASE_URL` окружения игнорируется.

## Где результаты

Каждый запуск раздела создаёт папку `results/stage-2/<папка раздела>/<время UTC>/`, например `results/stage-2/tron-sources/20261014T124823Z/`. Имена папок: `tron-sources`, `bridges`, `case-001`, `scenarios`, `llm`, `projection`, `foundation-probes`.

| Файл | Содержание |
|---|---|
| `config.json` | дата, коммит git (и признак незакоммиченных изменений), хеш исходного кода `source.sha256` (src/ledgerhunt, run_stage2.py, pyproject.toml, requirements.lock), версии Python и пакетов, профиль машины, наличие ключей (true/false), командная строка, точная команда для повтора, режим HTTP, настройки раздела |
| сырые файлы раздела | JSONL/JSON с исходными данными замера |
| `http-metrics.jsonl` | по строке на HTTP-запрос: источник, шаблон эндпоинта, статус, задержка, попытки, байты, класс ошибки |
| `http-summary.json` | сводка по источникам: число запросов, ошибки, повторы, 429, задержки p50/p95/max |
| `summary.json`, `summary.md` | итог раздела |

`results/stage-2/<раздел>/latest.json` указывает на последний завершённый запуск. Суммы в файлах данных — строки с точной десятичной записью, не числа с плавающей точкой.

## Сырые ответы и офлайн-повтор

Все ответы внешних API сохраняются в `data/http-store/`:

- `objects/<первые 2 символа>/<sha256 тела>` — тело ответа байт в байт (адресация по содержимому);
- `index.jsonl` — по строке на ответ: ключ запроса (источник, метод, URL без секретов, отсортированные параметры, JSON-тело), sha256 тела, статус, часть заголовков (лимиты, тип, дата), задержка, число попыток, размер, время, метка запуска.

Режимы HTTP: `record` (по умолчанию: живой запрос и сохранение), `replay` (только из хранилища, без сети), `cache` (из хранилища, если запрос уже был, иначе живой запрос с сохранением), `live` (живой запрос без сохранения). `--replay` повторяет весь прогон без сети на любой машине, где есть `data/http-store/`.

`.gitattributes` помечает `data/http-store/objects/**` и хранилища сценариев `tests/scenarios/**/http-store/objects/**` как двоичные файлы (для `tests/fixtures/case-001/raw/` — свой `.gitattributes`), чтобы git не менял в них переводы строк и хеши оставались верными.

**Что не попадает в git.** Тела ответов LayerZero Scan, NEAR Intents 1Click и TronScan (условия первых двух не разрешают хранить данные, от TronScan ждём письменного согласия) остаются только на ПК, где их записали: их исключают сгенерированные `.gitignore` в каждом хранилище, а строки индекса без тел коммитятся; после каждого живого прогона списки обновляются командой `python -m ledgerhunt.core.restricted`, в свежем клоне `--replay` пропускает разделы `bridges` и `case001` с понятным сообщением. Отложенный набор сценариев тоже не в git: в репозитории остаются только `tests/scenarios/holdout/README.md` и `manifest.json` с хешами, а сам набор передаётся владельцам архивом.

Особенности повтора:
- При `--replay` процесс не выходит в сеть, даже если клиент создан с явным режимом `live`, `record` или `cache`: такой запрос завершается ошибкой «network request refused» (код выхода 3), а не уходит в сеть молча.
- Повтор оценки моделей бесплатный: `python run_stage2.py --replay --llm` пересчитывает результаты из записанных ответов Claude, без обращений к API и без ключа. Без `--llm` раздел пропускается и при повторе.
- Если один и тот же запрос записан несколько раз, повтор отдаёт последнюю запись. Для неизменных данных блокчейна это не важно; для запросов текущего состояния (например, баланс «сейчас») и для задержек повтор старого запуска после нового живого прогона покажет значения нового.
- Часть веток кода выбирается по наличию ключей в `.env` на машине, где идёт повтор (значения не важны: ключи не входят в ключ запроса). Без ключа TronGrid источник в итогах называется `trongrid_keyless`, без ключа Etherscan раздел `bridges` идёт по ветке без ключа. Для повтора «один в один» нужен тот же набор ключей, что указан в `secrets_present` исходного запуска.

## Вежливость к источникам

Все агенты работают с одного IP, поэтому ограничитель частоты общий для всех процессов на машине (состояние в `.cache/ratelimit/`). Значения по умолчанию, запросов в секунду на хост:

| Хост | Лимит |
|---|---|
| api.trongrid.io без ключа | 1 |
| api.trongrid.io с ключом | 10 (отдельная квота) |
| apilist.tronscanapi.com | 1 |
| eth.blockscout.com | 3 |
| остальные | 2 |

При ответах 429 и 5xx, тайм-аутах и обрывах соединения запрос повторяется с экспоненциальной задержкой и случайным разбросом (до 5 попыток), заголовок `Retry-After` учитывается. После 429 от TronGrid пауза не меньше 5 с, и она распространяется на все процессы.

## Для авторов разделов

Каждый раздел — модуль `src/ledgerhunt/stage2/<имя>.py` с функцией `run(args) -> int`. Новый раздел добавляется одной строкой в `REGISTRY` в `src/ledgerhunt/stage2/__init__.py`. Минимальный шаблон:

```python
from ledgerhunt.core.results import start_run
from ledgerhunt.sources import TronGridClient

def run(args) -> int:
    ctx = start_run("tron-sources", config={"window": "2026-09-21"})  # имя папки в results/stage-2/
    http = ctx.http_client()            # общий клиент: лимиты, повторы, запись, метрики
    tg = TronGridClient(http)           # ключ берётся из .env, если он есть
    page = tg.trc20_transfers_page("TYGdh7qysHLr3A4gVGivcRwSg79PpVzgNn", limit=50)
    ctx.write_jsonl("raw/transfers.jsonl", page.data["data"])
    ctx.finish({"rows": len(page.data["data"])}, "# Итог\n...")
    return 0
```

Если что-то нельзя измерить сейчас (нет ключа или аккаунта), раздел записывает «не измерено: <причина>» и что для этого нужно.
