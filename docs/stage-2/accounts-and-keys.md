Список служебных аккаунтов и ключей, которые заводит владелец (решение 1.9 в [stage-2-decisions.md](../spec/stage-2-decisions.md)). Цены и условия прочитаны на официальных страницах 2026-10-14; цены без НДС, если не сказано иное. Ссылки на источники — в конце документа, в тексте они обозначены [S1], [S2] и т. д. Пометка «не проверено» означает, что первичный источник прочитать не удалось.

Ключи хранятся только в файле `.env` в корне репозитория (он в `.gitignore`) и читаются кодом через `ledgerhunt.core.config`. В результаты замеров попадает только факт наличия ключа (true/false). Имена переменных совпадают с [.env.example](../../.env.example); новые имена помечены «новая переменная».

## 1. Нужно сейчас для замеров

### 1.1 Anthropic Claude API

- **Аккаунт.** Организация ООО WHOMEVER в Claude Console (platform.claude.com). Ключ уже записан в `.env` (по отчёту фундамента `secrets_present.ANTHROPIC_API_KEY = true`).
- **Срочно: перевыпуск ключей.** В чат 2026-10-14 открытым текстом были отправлены три ключа: Anthropic, TronGrid и Etherscan. Все три нужно перевыпустить; ниже — порядок для Anthropic, для TronGrid и Etherscan — в их кабинетах. В текст задания этого прогона был вставлен ключ Anthropic открытым текстом. Ключ, попавший в чат, журнал или промпт, считается скомпрометированным. Владельцу нужно в Console отозвать его, создать новый ключ в отдельном workspace (ниже) и самому вписать его в `.env`. Ключи нельзя пересылать в чат, мессенджер или почту.
- **Уровни и потолки расходов** [S1]. Уровни Start, Build, Scale; потолок расходов в месяц: Start — $500, Build — $1 000, Scale — $200 000; у Custom потолка нет. Новая организация может начать с уровня Evaluation, лимиты которого ниже стандартных и не опубликованы; они растут автоматически по мере истории расходов. Текущий уровень виден на странице Limits в Console. Поднять уровень можно кнопкой «Request tier increase». При достижении потолка уровня API отвечает HTTP 429 (`enforced_spend_limit_reached`) до 00:00 UTC первого числа следующего месяца.
- **Лимиты запросов уровня Start** [S1]: у Claude Opus 5.5, Sonnet 5.5 и Haiku 5.5 у каждой модели отдельно 1 000 запросов в минуту, 2 000 000 входных токенов в минуту (токены, прочитанные из кеша, не считаются) и 400 000 выходных токенов в минуту. Batch API: 1 000 запросов в минуту, до 200 000 запросов в очереди.
- **Свой лимит расходов** [S1]. Console → Settings → Billing → Spend limits → «Adjust limit»/«Set limit»; значение не выше потолка уровня. При достижении своего лимита API отвечает HTTP 400 `invalid_request_error`. Лимиты можно задать и отдельному workspace (кроме workspace по умолчанию).
- **Рекомендация.** Завести workspace `ledgerhunt-stage2` с лимитом расходов (предлагаю $50 на Этап 2 — решает владелец; потолок case-001 по заданию $5) и выпускать ключ замеров только в нём. Для production позже — отдельный workspace и отдельный ключ.
- **Цены** [S2], за 1 млн токенов (вход / запись кеша на 5 мин / чтение кеша / выход): Haiku 5.5 — $0.10 / $0.125 / $0.01 / $0.50 (для промптов до 100 000 токенов; свыше — $0.50 / $0.625 / $0.05 / $2.50); Sonnet 5.5 — $2 / $2.50 / $0.10 / $10; Opus 5.5 — $4 / $5 / $0.20 / $20. Batch API — скидка 50%. Обработка только в США (`inference_geo: "us"`) — множитель 1.1 [S2][S3]. Цены совпадают с указанными владельцем в п. 1.2.
- **Регион.** Узбекистан есть в списке поддерживаемых стран (Supported Regions Policy, действует с 2026-05-12) [S4].
- **Условия хранения данных** — в [anthropic-data-terms.md](anthropic-data-terms.md).
- **Доступ:** владелец (владелец организации, оплата), ведущий инженер (ключ workspace замеров в `.env` на ПК). Код получает ключ только через `make_anthropic_client()`.

### 1.2 TronGrid (ключ API, план BASIC)

- **Аккаунт:** регистрация на www.trongrid.io, в кабинете создаётся ключ.
- **План BASIC** [S5]: $0, 100 000 запросов в сутки, до 3 ключей на аккаунт. В коде сайта есть ещё TRIAL на 500 000 запросов в сутки (условия не опубликованы) и Custom по заявке; у Developer, Team и Business вместо цены стоит «???» — публичных платных тарифов нет. Страница цен рисуется скриптом, значения прочитаны из кода сайта (`bundle.29481f13.js`).
- **Частота с ключом в документации не опубликована.** Страница лимитов (обновлена 2026-09-08) прямо говорит не зашивать числа в код и сверяться с кабинетом и ответами сервиса [S6]; в старых версиях документации встречалось 15 запросов в секунду. Без ключа — 3 запроса в секунду: в журнале изменений сайта (версия v1.10.0, дата «December 23», год не указан) лимит без ключа снижен с 10 до 3 [S5].
- **Замер (раздел `tron_sources`, [tron-sources.md](tron-sources.md), раздел 1).** С ключом сервер сам называет в ответе 429 лимит 15 запросов в секунду на ключ и паузу 30 с после превышения; устойчиво без ошибок держится 10 запросов в секунду (450 из 450 за 45 с, оба прогона), при 13 запросах в секунду уже был 429. Без ключа сервер называет 3 запроса в секунду и паузу 5 с; устойчиво — 2 запроса в секунду (120 из 120 за 60 с), ровный поток в 3 запроса в секунду иногда упирается в 429. Замер шёл с одного IP одного ПК; на сервере его нужно повторить. Действует ли лимит 15 запросов в секунду на ключ или на аккаунт (до 3 ключей) и что происходит после исчерпания суточной квоты, не проверено.
- **Условия** (Terms of Service от 2026-09-24) [S5]: запрещено перепродавать, сублицензировать и давать третьим лицам доступ к сервису или ключам; ключ конфиденциален; право Сингапура, арбитраж SIAC. Прямого запрета коммерческого использования в тексте нет (наше прочтение).
- **Ключ** передаётся только заголовком `TRON-PRO-API-KEY` (так уже сделано в `TronGridClient`).
- **Доступ:** владелец (аккаунт), ведущий инженер (`.env`).

### 1.3 Платный узел TRON: сравнение и рекомендация

Зачем нужен: квитанции транзакций (`gettransactioninfobyid`) и вызовы контракта на чтение у оператора, отличного от TronGrid (G5, G6). Бесплатный PublicNode для case-001 (транзакции 2026-09-21) возвращает `{}` — нужен узел с полной историей.

| TRON | Архивный режим TRON отдаёт полную историю блоков и транзакций (без исторического состояния) [S8]; запрос к полному узлу — 1 RU, к архивному — 2 RU [S7]; `/wallet`, `/walletsolidity`, `/jsonrpc` — по статье самого Chainstack [S12] | TRON поддерживается (для TRON есть отдельный продукт Limitless Node: полный узел от $150 в месяц за 25 запросов в секунду); стоимость методов TRON в CU на общих узлах не опубликована [S9] | TRON на странице цен указан только в Special Data API; Node API для TRON не подтверждён [S11] |
| Ethereum в том же аккаунте | да | да | не проверено |
| Условия | ToS (июнь 2026): доступ «для внутренних деловых целей» клиента (§3.1), запрет делать сервис доступным третьим лицам (§4.2(i)); бесплатный план «как есть», может быть приостановлен (§2.4); право Сингапура [S13] | ToS (2026-07-20): лицензия «для внутренних деловых целей» (§6.2(1)), запрет перепродажи сервиса (§6.4(6)), разрешено использовать публичные данные блокчейна (§10.9); право Англии и Уэльса [S10] | не прочитаны |

**Рекомендация: Chainstack** как `TRON_RPC_URL`.
1. Документировано, что архивный режим TRON отдаёт полную историю транзакций; это то, чего не хватило у PublicNode на case-001.
2. Предсказуемая цена: 1 или 2 RU за запрос. У GetBlock и Nodit вес методов TRON в CU не опубликован, стоимость графа на 1 000 адресов заранее не посчитать.
3. План — Growth за $49 в месяц. У Developer по странице цен архива нет [S7], а квитанции case-001 (2026-09-21) — данные трёхнедельной давности, которых не хватило уже у PublicNode; поэтому для них, вероятно, нужен Growth. Developer можно взять только для пробы подключения; на живом узле архивность ни одного плана не проверена.
4. Тот же аккаунт даёт Ethereum (`ETH_RPC_URL`, п. 1.4) — основной источник Ethereum для участков мостов.
5. Это продолжение решения G5 из Этапа 1.

Риски и что проверить: формулировка «для внутренних деловых целей» требует письменного подтверждения, что отчёты клиентам на основе ответов узла допустимы (как и записано в Этапе 1); бесплатный план может быть приостановлен; что узлы Chainstack не проксируют TronGrid, ещё не проверено (проба `tron_sources`).

**Второй провайдер** (`TRON_RPC_URL_2`, по желанию сейчас): GetBlock Free для сверки, в production — Starter за $49. Nodit не рекомендую, пока не подтверждён Node API для TRON.

**Как завести:** аккаунт Chainstack → проект → узел TRON Mainnet (Global Node) → скопировать HTTPS-адрес узла целиком в `TRON_RPC_URL`. Ключ встроен в адрес, поэтому весь URL считается секретом и в журналы не попадает.

### 1.4 Ethereum для участков мостов

Рекомендация совпадает с [bridges-and-ethereum-sources.md](bridges-and-ethereum-sources.md), раздел 10, и принята ведущим инженером:

| Участок | Основной источник | Второй источник |
|---|---|---|
| Ethereum: квитанции и логи (все мосты) | платный архивный Ethereum RPC в том же аккаунте Chainstack, что и узел TRON (`ETH_RPC_URL`); не измерен, нужен живой замер | Blockscout PRO (`BLOCKSCOUT_API_KEY`, бесплатный ключ; условия коммерческого использования подтвердить письменно) |
| Etherscan API v2 | в продукте не используется | — |
| USDT0 / LayerZero | разбор `OFTSent` в TRON и `OFTReceived(guid)` в Ethereum (замер: 6 из 6 совпадений с LayerZero Scan); LayerZero Scan в продукте не используется | квитанция из второго источника |
| NEAR Intents 1Click | статус с ключом партнёра; ответы хранить не дольше 24 часов | поиск выплаты по данным блокчейна |

Для разработки без ключей годится dRPC (измерен, условия не читались); в продукт он не входит.

- **`ETH_RPC_URL` — Chainstack Ethereum Mainnet** в том же проекте, что и узел TRON, план Growth (п. 1.3). Ограничение `eth_getLogs`: на Developer — 100 блоков за запрос, на Growth и выше — 10 000 блоков [S14]. Для чтения коротких участков моста (минуты) этого достаточно. Публичный `ethereum-rpc.publicnode.com` для продукта не годится: в замере он отдавал пустые квитанции по существующим транзакциям и не отдаёт историю логов без токена ([bridges-and-ethereum-sources.md](bridges-and-ethereum-sources.md), разделы 3–4).
- **`BLOCKSCOUT_API_KEY` — Blockscout PRO API, бесплатный ключ** на dev.blockscout.com, без карты [S15]. Free: 5 запросов в секунду, 100 000 кредитов в сутки; Builder $49 (100 млн кредитов в месяц, 15 запросов в секунду); Pro $199; Business $999. Запрос стоит 20 кредитов по умолчанию, 30 — для `token-transfers` и `logs`, то есть бесплатно около 3 300 таких запросов в сутки [S16]. Документация предупреждает, что публичные хосты сетей (например, eth.blockscout.com) закрыты защитой от ботов и скриптовые запросы могут получить 403, и советует ходить на `api.blockscout.com` с ключом [S16]. Пример в документации дан только в стиле `module/action` с параметром `chain_id`; работает ли ключ на `eth.blockscout.com` и в каком виде вызывать REST v2 через `api.blockscout.com`, не проверено. Условия использования PRO API не прочитаны (страница не найдена) — до production прочитать.
- **Etherscan API V2 — в продукт не брать.** Free ($0, 3 вызова в секунду, 100 000 в сутки), Lite ($49) и Standard ($199) разрешены только для «Personal & Research»; коммерческое приложение — от Advanced за $299 в месяц (20 вызовов в секунду, 500 000 в сутки) [S17]. Условия API (обновлены 2026-10-01): обязательная подпись «Powered by Etherscan.io APIs», запрет перепродажи данных в сыром виде, хранение дольше разрешённого срока — по отдельной лицензии, запрет конкурирующих сервисов [S18]. Для нашей задачи достаточно платного RPC и Blockscout PRO.
- **Бесплатный ключ Etherscan уже есть в `.env`** (`ETHERSCAN_API_KEY = true` в `config.json` всех прогонов разделов Этапа 2, кроме ранней проверки эндпоинтов `foundation-probes`) и использовался только для исследования Этапа 2: в разделе мостов — 27 вызовов на прогон (54 HTTP-запроса за два прогона с записью), в case-001 — 3 запроса меток, сделанные один раз. В продукт и в вертикальный срез этот ключ не берём. Оставлять ли его для разработки или отозвать — решение владельца.

### 1.5 API мостов

- **LayerZero Scan** (`scan.layerzero-api.com/v1`): ключ не нужен, лимиты не опубликованы [S19]. Важно: условия Scan API (обновлены 2025-07-23) дают лицензию только для личного некоммерческого использования, запрещают копировать и распространять данные (кроме кеша браузера), требуют указывать LayerZero как источник; запрещённое возможно только с письменного разрешения LayerZero Labs [S20]. **В замерах Этапа 2 Scan API уже использовался**, без ключа: в разделе мостов — 60 HTTP-запросов за два прогона с записью (по 30), в case-001 — по 3 запроса за живой прогон (2 при перевыгрузке и 1 в эталонном прогоне), 6 за два прогона. Ответы сохранены только на ПК, где их записали, и в git не попадают. **В продукте LayerZero Scan не используется:** получатель и транзакция назначения USDT0 берутся из блокчейна (`OFTSent` в TRON → `OFTReceived(guid)` в Ethereum), замер дал 6 из 6 совпадений со сканером ([bridges-and-ethereum-sources.md](bridges-and-ethereum-sources.md), разделы 7.1 и 10). Допустимость уже сделанного использования и хранения ответов — вопрос юристу.
- **NEAR Intents 1Click** (`1click.chaindefuser.com`): ключ партнёра выдаётся в Partner Dashboard (partners.near-intents.org) и передаётся заголовком `X-API-Key`; `Authorization: Bearer` тоже принимается [S21]. По описанию эндпоинта `GET /v0/status` авторизация обязательна, JWT назван устаревшим способом [S22], хотя наш запрос без ключа 2026-10-14 вернул 200 (отчёт фундамента) — расхождение документации и поведения. Без ключа к котировкам добавляется комиссия 0.25% [S21], но котировки нам не нужны. Цена партнёрского доступа не найдена. Условия 1Click запрещают хранить данные дольше 24 часов ([bridges-and-ethereum-sources.md](bridges-and-ethereum-sources.md), раздел 9): ответы статуса — только указатель на данные блокчейна, а не доказательство. Рекомендация: завести ключ сейчас, чтобы замер не зависел от недокументированного доступа без ключа; значение записать в `NEAR_INTENTS_JWT` (имя переменной историческое).
- **Rango:** ключ выдают по тикету в Discord, для B2B-партнёров бесплатно; ключ передаётся параметром запроса `apiKey`; есть тестовый ключ с низким лимитом [S23]. Эндпоинт статуса требует `requestId` свопа, созданного через Rango, поэтому для чужих транзакций он, по нашему прочтению, неприменим; участок Rango в case-001 разбирается из данных транзакции в блокчейне. Ключ сейчас не нужен.

## 2. Нужно позже (вертикальный срез и production)

### 2.1 Google OAuth для входа клиентов

- **Что завести:** проект Google Cloud на компанию → Google Auth Platform: Branding (название, e-mail поддержки, логотип, домашняя страница, политика конфиденциальности, авторизованные домены), Audience — тип External, статус «In production», Data access — только `openid`, `email`, `profile`; затем OAuth-клиент типа Web application с адресами возврата на нашем домене.
- **Проверка приложения** [S24][S25]. Для приложений только с несекретными (non-sensitive) областями доступа полная проверка Google не обязательна. Базовые области входа (`email`, `profile`, `openid`) не попадают под предупреждение о непроверенном приложении, лимит в 100 пользователей и истечение доступа через 7 дней в режиме Testing. Чтобы на экране согласия показывались название и логотип, нужна облегчённая проверка бренда (brand verification).
- **Требования проверки бренда** [S25]: домашняя страница на собственном домене, которая описывает приложение (не только страница входа) и ссылается на политику конфиденциальности; политика на том же домене, со ссылкой и с экрана согласия, описывает, как используются данные Google; все авторизованные домены подтверждены в Google Search Console владельцем или редактором проекта; контактный e-mail проекта актуален.
- **Нужно до этого:** домен, сайт и политика конфиденциальности (текст — после юриста). Сроки проверки бренда в прочитанных документах не указаны. Отдельных платежей за OAuth не нашли; квоты не проверены.
- **Переменные** (новые): `GOOGLE_OAUTH_CLIENT_ID` (не секрет), `GOOGLE_OAUTH_CLIENT_SECRET` (секрет; суффикс `_SECRET` маскируется автоматически).
- Имя и e-mail из Google — персональные данные клиента, они идут в хранилище персональных данных по юрисдикции клиента (решение 1.3).

## 3. Доступ к ключам и правила

| Кто | Что видит |
|---|---|
| Владелец | Все аккаунты: владелец, оплата, выпуск и отзыв ключей |
| Ведущий инженер | Ключи разработки в `.env` на своём ПК; ключи production — на сервере через SOPS + age |
| Код и агенты | Только через `ledgerhunt.core.config` (`get_secret`, `make_anthropic_client`, `TronNodeClient.from_env`, `EthRpcClient.from_env`); в журналы, сырые ответы и результаты ключи не попадают |
| Клиенты, подрядчики | Никаких ключей |

- Ключи вписывает владелец или ведущий инженер прямо в `.env`. Не пересылать их в чатах, мессенджерах, почте, задачах для агентов.
- Ключ, попавший в чат, журнал или репозиторий, — отозвать и выпустить новый.
- Разные ключи для разработки и production; у каждого платного сервиса — лимит расходов там, где он есть.
- После заполнения `.env` проверить командой `.venv\Scripts\python -m ledgerhunt env`: она показывает только true/false для каждого ключа.
